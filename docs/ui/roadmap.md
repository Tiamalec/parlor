# UI Refactor Roadmap

## 范围分层

- 主题缺陷修复：只消除系统 palette 泄漏和不可读背景。
- 主题基础设施：ThemeManager、双主题 tokens、QSS/Palette、IconProvider、RichTextRenderer。
- 视觉组件迁移：导航、聊天、通讯录、AI 任务、设置逐页迁移。
- 功能扩展：不属于 UI 重构，必须单独立项。

## 阶段 3：主题基础设施

### 完成记录（2026-11-17）

- 实现不可变 `ThemeTokens`、完整 Light/Dark 语义色板、`ThemeSnapshot` 与主题 revision。
- 实现 `ThemeManager`，支持 Light、Dark、System，使用 `QSettings` 持久化，并监听 Qt `colorSchemeChanged`。
- 启动时在创建主窗口前同步应用 QPalette 与 QSS，运行时切换不重建窗口、不触发 Store topic 或网络请求。
- 统一 canvas/surface/elevated、滚动区、输入框、列表、菜单、弹窗和消息气泡的主题规则；移除 V2 中本阶段涉及的局部颜色 QSS。
- MessageBubble、Markdown、代码块、Mention、fallback Avatar 与 ToggleSwitch 可随主题原位刷新；保持消息对象、编辑内容、Mention ID、滚动位置和业务引用。
- 设置页增加“跟随系统 / 浅色 / 深色”选择，不改变页面整体布局。
- 新增 6 项主题测试；当前全量 62 项测试通过 61 项，实时 Ollama 测试按配置跳过。
- Qt offscreen 完成 Light/Dark/System 多页面视觉矩阵，System 与对应显式主题截图一致；macOS Qt cocoa 完成应用内容浅/深色渲染检查。
- 未验证 Windows、Linux、macOS 原生标题栏与原生文件对话框的强制主题一致性。
- 860px 宽度下聊天区仍存在既有横向滚动与头像边缘受压；该问题属于页面响应式布局，不在主题基础设施阶段调整，页面迁移时需单独验收。

### 修改范围

- `ThemeTokens`、`ThemeManager`、QSS builder、QSettings、最小 QPalette fallback。
- 设置页仅增加主题模式选择，不改其他布局。

### 自动化门槛

- token 完整性与对比度测试。
- Light/Dark/System 模式解析与系统信号测试。
- 切换前后 Store、当前会话、消息和输入内容不变。

### 人工门槛

- 系统 Light/Dark × 应用三模式，无启动闪烁和混合底板。
- 原生标题栏/文件对话框若跟随系统而非强制模式，按已知平台限制记录，不宣称完全一致。

### 回滚

- 阶段 3 为独立 Git 提交，可回滚到阶段 2 提交 `66b8949`。
- 主题偏好仅存储于 `QSettings`；旧版本忽略该键，无数据迁移依赖。

## 阶段 4：公共视觉组件

### Navigation Rail 完成记录（2026-11-19）

- V2 左侧导航收敛为 76px 桌面 Navigation Rail，导航项固定 56px 高，图标为 20px、标签为 11px；移除无功能意义的顶部星形装饰。
- 消息、通讯、AI 与管理员入口位于上部，设置入口通过布局伸缩固定底部；管理员入口继续沿用现有角色可见性逻辑。
- 使用 Qt Resource 内置消息、通讯、AI、管理和设置五个精选 Lucide SVG，并按 ThemeTokens 动态生成 1x/2x DPR 的普通、悬停、选中和禁用图标。
- 导航项提供 hover、pressed、checked、focus、disabled 状态、tooltip、accessibleName 和方向键切换；消息入口增加聚合未读数标记。
- 页面索引、路由 Signal 与页面业务对象保持不变；运行时切换主题会刷新图标，但不会重建导航或丢失当前选中页面。
- Qt offscreen 与真实 macOS cocoa 环境完成 Light/Dark、1180×760 和 720×520 截图验收；短窗口设置入口保持底部且无截断、溢出。
- 22 项 V2 UI/主题测试通过；全量 65 项测试通过 64 项，1 项显式启用的本地 Ollama 实时测试跳过；`compileall` 与 Qt Resource 再生成一致性检查通过。
- Windows、Linux 原生字体、图标栅格化和焦点绘制尚未验证。

### 修改范围

- Qt Resource 与精选 Lucide SVG。
- 导航、IconButton、PageHeader、StatusBadge、SettingsSection 等。

### 完成条件

- Emoji 不再承担导航/操作图标。
- 所有新增图标在 1x/2x DPR 和两主题下清晰。
- 组件键盘焦点、tooltip、accessibleName 完整。

## 阶段 5：页面迁移

页面按独立子阶段迁移并分别验收。聊天、通讯录、AI 任务中心与设置页已经完成迁移；客户端管理页仍需独立推进，不得在单次修改中夹带未授权页面。

### 聊天与通讯录完成记录（2026-11-19）

- 会话列表调整为 64px 紧凑行，增加稳定选中态、完整时间与未读展示；小于 1040px 时改为会话列表与聊天主体单页切换，消除 860px 横向挤压。
- 聊天头部补充群成员数与 Agent 状态；消息头像、发送者、时间、Mention、图片占位、普通气泡和 AI 气泡沿用统一语义主题。
- 输入工具栏、编辑框和消息区改为连续表面；深色主题下不再出现白色输入底板或割裂边界。
- 仅当协议 `content_format` 为 Markdown 时渲染结构化富文本；普通消息及普通格式 AI 消息保持纯文本，外部图片和 HTML 继续被阻止。
- 通讯录增加联系人/群聊搜索、分段选择、在线状态、群成员摘要、加载/错误/空结果状态和统一资料详情。
- 小于 720px 的通讯录采用列表与资料单页切换，宽屏保持目录/详情双栏；资料重复刷新不再叠加操作按钮。
- Qt offscreen 与真实 macOS cocoa 环境完成 Light/Dark 截图验收，覆盖 1180×760、860×600、720×520；未发现深灰泄漏、不可读文字、白色卡片突兀或输入区割裂。
- 13 项 V2 UI 测试通过；全量 62 项测试通过 61 项，1 项显式启用的本地 Ollama 实时测试跳过；`compileall` 构建检查通过。
- Windows、Linux 桌面渲染及不同系统字体度量未验证，保持平台验收待办。

### 本阶段未包含

- 客户端管理页仍按后续页面迁移任务处理。
- 导航 Emoji 替换与 Lucide 资源仍属于阶段 4 公共视觉组件，不在本次页面改造中夹带。
- `application.py` 拆分仍留在阶段 6，本次未改变业务服务、Store、Signal 或协议边界。

### AI 任务中心与设置页完成记录（2026-11-19）

- AI 任务中心由大卡片改为 64px 起的紧凑工作台行，统一显示任务类型、来源会话、请求人、时间、状态、详情和可用结果操作。
- 增加状态、任务类型、来源会话三级筛选，以及筛选计数、空结果、加载、提交反馈和服务错误状态；任务详情采用独立对话框，历史活动数据与原有结果跳转保持不变。
- 新建任务仅在 Agent 在线且存在会话时可用；回答问题任务才显示问题输入，其他任务不再呈现无效字段。
- 设置页重组为账号资料、外观主题、聊天偏好、消息通知、AI 助手、连接与诊断六类；宽屏采用侧栏导航，窄屏切换为紧凑分类选择。
- 账号头像、主题模式和退出登录继续使用已有能力与持久化路径；连接、Agent 状态和快捷键信息只读展示。通知、聊天偏好、AI 默认范围和诊断导出因缺少完整后端或持久化支持，明确标记为“待实现”，未提供无效开关。
- 设置内容使用分组与分隔线构建层级，避免整页空白卡片；危险操作、反馈提示、表单和状态徽标均使用现有语义主题规则。
- Qt offscreen 与真实 macOS cocoa 环境完成 Light/Dark 截图验收，覆盖 1180×760 与紧凑窗口；未发现背景泄漏、不可读文字、突兀白色卡片或主题割裂。
- 20 项 V2 UI/主题测试通过；全量 63 项测试通过 62 项，1 项显式启用的本地 Ollama 实时测试跳过；`compileall` 构建检查通过。
- Windows、Linux 桌面渲染、系统字体度量与原生通知能力未验证，保持平台验收待办。

## 全局验收矩阵

- 尺寸：720×520、860×600、1180×760、≥1280 宽屏。
- 平台：实际覆盖的平台明确记录；未运行的平台标记未验证。
- 主题：系统 Light/Dark；阶段 3 后增加应用 Light/Dark/System。
- 功能：登录、会话切换、文本/图片发送、Mention、Agent、搜索、详情、任务结果、设置与重连。
- 可访问性：正文 AA、焦点可见、状态不只依赖颜色、图标按钮有名称。
